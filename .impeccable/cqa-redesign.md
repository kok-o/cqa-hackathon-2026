# CQA redesign direction

Mode: Operate.

## Confirmed direction

The user rejected the existing generated-looking layout and explicitly approved rebuilding the interface around a separate dialogue index and a spacious, evidence-centered review. This is a code-led replacement of that visual world, preserving the working API, assessment logic, source data, appeal history, drafts and official export. The approved proposal is the direction authority.

## First viewport

The initial desktop view shows a narrow neutral navigation rail and an independent, full-width dialogue table. State filters and import sit above search and optional filters. Actual excerpts lead the rows; identity, language, channel, status, score and gross-error flag remain aligned and independently readable. There is no permanently open transcript or result panel in the index.

Opening a row enters a dedicated review route. A compact identity and navigation header sits above two areas: a broad, readable transcript and a narrower assessment. The source dominates the available reading width. On mobile, two tabs switch the same review between Conversation and Assessment. The queue is available on demand.

## Signature interaction

Open a criterion, inspect its explanation, and select its evidence. The original source position is revealed, a collapsed bot prelude opens when necessary, and the exact substring or checked range is highlighted. The return control restores focus to the initiating criterion. A review decision preserves both original and revised outcomes with its reason.

## Cross-surface rules

- White work surfaces, gray navigation, graphite text, restrained Freedom green for meaningful action and selection.
- One locally bundled type family, readable 16px desktop transcript text, clear alignment rather than repeated card shells.
- Evaluation settings appear in a launch dialog with real target count and version.
- Checklist editing uses a criterion index and a single form with version-bound drafts.
- Summary is a compact list of actual findings; export is parameters followed by a receipt derived from the same validated document that is downloaded.
- Hash routes support application sections and dialogue identity. Source snapshots and evaluation versions remain explicit in the UI.
- Short state transitions obey reduced motion; focus and selection survive the change.

## Scope and review

The implementation is intended to cover index, detail, rules, summary, import, launch and export at 1366×768 and narrow widths down to 320px. The actual user browser-panel width belongs in responsive verification. This contract records the agreed direction and implementation intent; it does not claim a final review disposition or passing QA.
