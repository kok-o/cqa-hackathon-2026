# CQA — Conversation Quality Analytics

Командный проект Freedom Broker CQA Hackathon, 7–8 ноября 2026 года.

Цель — оценивать диалоги операторов по редактируемому чек-листу, показывать проверяемые доказательства и проводить спорную оценку через апелляцию до окончательного результата.

## С чего начать

1. Прочитайте [подробный план](docs/IMPLEMENTATION_PLAN.md) и [свою часть работы](docs/TEAM.md).
2. Согласуйте [контракты и архитектуру](docs/ARCHITECTURE.md).
3. Запустите каркас API и проверьте синтетические примеры.
4. Получите отдельный официальный PDF с восемью критериями и внесите его правила в конфигурацию. В репозитории есть учебный чек-лист для разработки форматов.

Это стартовое распределение по трём независимым частям. После запуска каждый участник берёт свой GitHub issue. Изменения общего контракта сначала согласуются втроём.

## Что уже подготовлено

- План по часам, приоритеты, задачи и критерии приёмки.
- Архитектура, API-контракт и схема жизненного цикла оценки.
- FastAPI-каркас с `/health`, `/api/demo/conversations` и OpenAPI `/docs`.
- Pydantic-контракты, TypeScript-типы, синтетические диалоги RU/KZ/EN и пример конфигурации.
- Скрипт получения DEV в локальную папку, проверка входного формата и стабильные ID реплик.
- [Профиль фактического DEV](docs/DATA_PROFILE.md) с подтверждённым объёмом и распределением языков.
- Шаблон инструкции для модели, план проверки качества и сценарий пятиминутной защиты.
- Копия задания с удалённой подписанной ссылкой доступа. Исходник остаётся у организаторов и участников.
- Предварительные исследования и утилиты в `reports/`, `research_notes/`, `hackathon-kit/`.

Текущая стадия — подготовленный старт разработки. Реальная AI-оценка, SQLite-хранилище, расчёт по официальному чек-листу и полноценные экраны входят в задачи команды.

## Выбранный стек

React + TypeScript + Vite для интерфейса. FastAPI + Pydantic для API и проверки структур. SQLite через стандартный `sqlite3` для локального прототипа. Модель подключается через один серверный модуль. Провайдер и название модели фиксируются после короткого сравнения на RU/KZ/EN.

Интерфейс использует относительный адрес `/api`. Для демонстрации планируется один сервер, раздающий собранный frontend. Изолированный корневой контейнер и отдельный API-адаптер помогут дальнейшему переносу интерфейса в HTML-компонент Dynamics 365.

## Запуск каркаса

Python 3.13 проверен локально. Команды выполняются из корня репозитория.

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
.\.venv\Scripts\python.exe -m unittest discover -s backend/tests -v
.\.venv\Scripts\python.exe -m uvicorn backend.cqa.main:app --reload --host 127.0.0.1 --port 8000
```

На macOS/Linux используйте `python3 -m venv .venv` и `.venv/bin/python`.

Откройте [локальную документацию API](http://127.0.0.1:8000/docs). В `.env` вставьте ссылку GET из исходного PDF в `CQA_DEV_URL`, затем выполните импорт.

```powershell
.\.venv\Scripts\python.exe scripts/fetch_dataset.py --group DEV
```

Скрипт сохраняет данные в `data/raw/DEV.json`. Контрольный `group_id` задаётся значением, которое объявят организаторы.

Frontend начинает работу по [инструкции Олжаса](frontend/README.md). Конкретные версии npm-зависимостей закрепляются в lockfile при создании приложения.
