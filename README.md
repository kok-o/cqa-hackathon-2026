# CQA — оценка качества диалогов

Локальный прототип Freedom Broker CQA Hackathon: импорт RU/KZ/EN, версионируемый чек-лист, доказательства, апелляции и пересчёт. React + TypeScript + Vite, FastAPI + Pydantic, SQLite.

**Модель сейчас не подключена по решению команды.** Работают загрузка и чтение диалогов, редактирование чек-листов и просмотр сохранённых результатов. Для новых AI-оценок нужен сервер модели и настройки в `.env`. Приложение не подставляет готовые оценки при отсутствии подключения.

**Официальные восемь критериев пока не предоставлены.** Начальный чек-лист содержит два учебных критерия. Формула — предварительное взвешенное среднее нормализованных ответов; её нужно сверить с правилами организаторов. Точность по официальному Ground Truth ещё не измерялась.

## Быстрый запуск на Windows

Нужны Python 3.13 и Node.js 22.12+ (локально проверены Python 3.13 и Node.js 24). Из корня проекта, первый запуск:

```powershell
.\scripts\start.ps1 -Setup
```

Скрипт создаёт `.venv`, устанавливает закреплённые зависимости, копирует `.env.example` только при отсутствии `.env`, собирает интерфейс и запускает приложение. Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000).

Следующий запуск: `.\scripts\start.ps1`. После изменений интерфейса: `.\scripts\start.ps1 -Build`. Альтернативный порт: `-Port 8001`. Остановка — Ctrl+C. База и история сохраняются в `data/runtime/cqa.sqlite3`.

На macOS/Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
test -f .env || cp .env.example .env
npm --prefix frontend ci
.venv/bin/python scripts/run.py --build
```

## Рабочий процесс

1. Загрузите JSON-файл организаторов или локальный DEV. Учебные примеры доступны отдельно и явно отмечены.
2. Выберите диалог: язык, канал, роли и исходные временные метки сохраняются. Аудиоплеер доступен, если у звонка есть ссылка на запись.
3. Измените или добавьте критерий и сохраните новую версию чек-листа. Настраиваются вес, тип ответа, шкала, варианты, N/A и требование аудио.
4. После подключения модели запустите оценку одного диалога или группы. Задачи имеют состояния и ошибки. Результат хранит снимок диалога, версию правил и сведения о модели.
5. Откройте доказательство для перехода к реплике. Для отсутствующего действия показывается проверенный диапазон. N/A означает неприменимость по правилам, needs_review — неполную проверку; неполнота не превращается в итоговый балл.
6. Подайте апелляцию по критерию. При пересмотре подтвердите результат или замените ответ с основанием. Итог пересчитывается, исходная оценка и история сохраняются.
7. Экспортируйте оценки в JSON. Новые версии правил не меняют историю старых запусков.

## Подключение модели позже

Заполните локальный `.env` и перезапустите API:

```dotenv
LLM_BASE_URL=
LLM_MODEL=
LLM_API_KEY=
LLM_TIMEOUT_SECONDS=45
LLM_CONCURRENCY=2
LLM_JSON_MODE=json_object
LLM_MAX_TOKENS=6000
```

LLM_BASE_URL — базовый адрес сервера, совместимого с Chat Completions, обычно с окончанием /v1. LLM_MODEL — точный ID модели. Ключ хранится только на сервере. Локальные серверы без авторизации могут работать с пустым ключом. Режимы ответа: json_object, json_schema и none; выбор зависит от сервера.

Полный диалог и актуальные инструкции отправляются выбранному провайдеру только при запуске оценки. Сервер проверяет типы ответов, границы шкал, критерии, точные цитаты и диапазоны. При некорректном ответе выполняется ограниченный повтор; сбой остаётся видимым. Структурированный формат сам по себе не гарантирует верную смысловую оценку.

Адаптер анализирует текст. Критерии, требующие прослушивания аудио, получают needs_review; наличие плеера не означает, что модель прослушала запись. Для оценки дикции/интонации потребуется аудиоадаптер после получения точных критериев.

Стоимость не выдумывается: LLM_INPUT_COST_PER_MILLION и LLM_OUTPUT_COST_PER_MILLION можно заполнить по актуальному тарифу в USD. Без тарифа/usage стоимость неизвестна. Модель, попытки, токены и время сохраняются.

## Данные и контрольный набор

Формат файла: DatasetExport с полями isSuccess, error, data.dataset_group_id, data.total_records, data.records. [Синтетический пример](fixtures/synthetic_dev.json). Диалог содержит conversation_id, language, channel, transcript, опционально audio_url. В реплике — timestamp, speaker, text.

Ключ диалога состоит из группы и ID. Повторный импорт не создаёт дублей. Изменение исходника не переписывает снимки прошлых оценок.

Реальный DEV находится локально в `data/raw/DEV.json` и не включается в Git. Для повторного получения задайте CQA_DEV_URL из исходного задания:

```powershell
.\.venv\Scripts\python.exe scripts/fetch_dataset.py --group DEV
```

Для контроля используйте объявленный организаторами group_id. Сохранённый JSON загружается через тот же интерфейс. Подписанные ссылки, ключи, настоящие транскрипты и runtime-БД не публикуются.

## Проверка и разработка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s backend/tests -v
npm --prefix frontend run build
```

Тесты используют изолированные тестовые ответы, не платные модели. Они проверяют механику, а не точность AI. Инструменты разметки и сравнения результатов находятся в [evaluation/](evaluation/). Результаты и повторение сквозного браузерного сценария — в [отчёте проверки](docs/VALIDATION.md).

Для разработки запустите в двух терминалах:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.cqa.main:app --host 127.0.0.1 --port 8000 --reload
npm --prefix frontend run dev
```

Vite перенаправляет /api на FastAPI. Собранное приложение обслуживает один сервер. [OpenAPI](http://127.0.0.1:8000/docs), [API-контракт](docs/API_CONTRACT.md), [расчёт](docs/SCORING.md).

## Подготовка к отбору

Основной критерий топ-50 — близость к Ground Truth на десяти неизвестных транскриптах. Точная метрика организаторов пока не раскрыта. После выдачи чек-листа нужно сверить шкалы, N/A, грубые ошибки и формулу, разметить проверочные примеры и измерить ошибки по языкам и критериям. Учебные метки не являются Ground Truth организаторов.

Защита: новый файл → оценка → доказательство → апелляция → новый итог → изменение критерия и повторная проверка. Сроки T+23/T+24 и пятиминутная защита описаны в [задании](docs/briefs/CQA_Student_Guide.pdf). Точный T0 сверяется с организаторами.
