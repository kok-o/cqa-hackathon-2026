# CQA — оценка качества диалогов

Локальный прототип Freedom Broker CQA Hackathon: импорт RU/KZ/EN, версионируемый чек-лист, доказательства, апелляции и пересчёт. React + TypeScript + Vite, FastAPI + Pydantic, SQLite.

Реальная оценка поддерживает OpenAI Responses API и серверы с Chat Completions. Подключение задаётся локальным `.env`; текущий статус виден в интерфейсе. При отсутствии подключения приложение сохраняет импорт, просмотр и настройку правил, но не подставляет готовые AI-оценки.

**Официальный чек-лист получен и сверён с PDF:** [восемь критериев](fixtures/checklist.official.json), веса 10 / 15 / 20 / 20 / 15 / 15 / 5 / 0, дискретные шкалы, пропорциональное перераспределение N/A. Грубые ошибки отмечаются отдельно и не обнуляют итог. Два учебных критерия оставлены для изолированных тестов. Рабочий экономичный профиль — **GPT-6 Luna / high**, промпт v6. Sol сохранён как отдельный модельный ориентир, а не Ground Truth. [Результаты и ограничения сравнения](docs/BENCHMARK_RESULTS.md). Без независимой экспертной разметки техническая успешность не доказывает точность по официальному GT.

[Файл DEV команды SetW](results/dev/results.json) содержит 65 успешных оценок Luna. Из них 57 получены в полном проходе v5 и 8 при адресном обновлении v6. Для десяти ответов N/A добавлены ссылки на подтверждающие реплики после сверки ассистентом. Решения и баллы сохранены. Получение оценок стоило около **$0,179** по токенам, включая сбой и заменённые ответы. Разработческие пилоты учтены отдельно. [Sol/v3](results/reference/sol-dev-v3.json) сохранён отдельно. [Порядок сдачи](results/README.md).

## Быстрый запуск на Windows

Нужны Python 3.13 и Node.js 22.12+ (локально проверены Python 3.13 и Node.js 24). Из корня проекта, первый запуск:

```powershell
.\scripts\start.ps1 -Setup
```

Скрипт создаёт `.venv`, устанавливает закреплённые зависимости, копирует `.env.example` только при отсутствии `.env`, собирает интерфейс и запускает приложение. Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000).

Следующий запуск: `.\scripts\start.ps1`. После изменений интерфейса: `.\scripts\start.ps1 -Build`. Альтернативный порт: `-Port 8001`. Остановка — Ctrl+C. База и история сохраняются в `data/runtime/cqa.sqlite3`.

На macOS/Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
test -f .env || cp .env.example .env
npm --prefix frontend ci
.venv/bin/python scripts/run.py --build
```

## Рабочий процесс

1. Загрузите JSON-файл организаторов или локальный DEV. Учебные примеры доступны отдельно и явно отмечены.
2. Выберите диалог. Язык, канал, роли и исходные временные метки сохраняются. Фильтр грубых ошибок работает по последней оценке текущей версии диалога с учётом апелляций. Вкладка «Сводка» показывает снижение по применимым критериям и ведёт к оценке, из которой оно получено. Аудиоплеер доступен, если у звонка есть ссылка на запись.
3. Измените или добавьте критерий и сохраните новую версию чек-листа. Настраиваются вес, тип ответа, шкала, варианты, N/A и требование аудио.
4. После подключения модели запустите оценку одного диалога или группы. Задачи имеют состояния и ошибки. Результат хранит снимок диалога, версию правил и сведения о модели.
5. Откройте доказательство для перехода к реплике. Для отсутствующего действия показывается проверенный диапазон. N/A означает неприменимость по правилам, needs_review — неполную проверку; неполнота не превращается в итоговый балл.
6. Подайте апелляцию по критерию. При пересмотре подтвердите результат или замените ответ с основанием. Итог пересчитывается, исходная оценка и история сохраняются.
7. Экспортируйте историю оценок в JSON. Новые версии правил не меняют старые снимки; изменение исходного текста снимает с текущего диалога устаревшую оценку. Для сдачи организаторам используется отдельный формат JSON 1.0 из приложения ниже.

## Подключение модели

Для экономичного OpenAI Responses-профиля заполните локальный `.env` и перезапустите API:

```dotenv
LLM_BASE_URL=https://api.openai.com/v1
LLM_API_STYLE=responses
LLM_MODEL=gpt-6-luna
LLM_API_KEY=
LLM_REASONING_EFFORT=high
LLM_TIMEOUT_SECONDS=180
LLM_CONCURRENCY=2
LLM_JSON_MODE=json_schema
LLM_MAX_TOKENS=16384
```

Профиль выбран по наблюдаемой стоимости, времени и проверкам правил; превосходство точности по GT не установлено. `LLM_REASONING_EFFORT` передаётся как `reasoning.effort`, а `LLM_MAX_TOKENS` — как `max_output_tokens`. Рабочая Luna использует high, лимит 16384 и тайм-аут 180 с. Историческое сравнение трёх моделей использовало max, 16384 и 300 с. В Responses лимит включает рассуждение и видимый ответ; слишком маленький лимит может дать незавершённый ответ. Поддерживаемые уровни зависят от модели ([официальная документация OpenAI](https://developers.openai.com/api/docs/guides/reasoning)). Адаптер всегда использует строгую JSON-схему в Responses и не понижает заданный уровень рассуждения молча.

Для ручного переключения без изменения ключа:

```powershell
python scripts/select_model.py luna-economy --apply
# Альтернативный профиль для отдельной перепроверки:
python scripts/select_model.py sol-reference --apply
```

После выбора перезапустите API. Без `--apply` команда только показывает настройки.
Sol-профиль использует max, 32768 токенов и 600 с; автоматических обращений к Sol
при работе Luna нет. Сохранённый исходный Sol-бенчмарк использовал прежний промпт
v3; новый запуск любого профиля применяет текущий промпт v6.

Для совместимого локального или другого Chat Completions сервера задайте его `LLM_BASE_URL`, `LLM_API_STYLE=chat_completions`, фактический `LLM_MODEL` и поддерживаемый `LLM_JSON_MODE`: `json_object`, `json_schema` либо `none`. Неиспользуемый `LLM_REASONING_EFFORT` оставьте пустым. Локальный сервер без авторизации допускает пустой ключ. Секрет `LLM_API_KEY` хранится только на сервере; для интерфейса не нужен отдельный ключ в браузере.

Полный диалог и актуальные инструкции отправляются выбранному провайдеру только при запуске оценки. Сервер проверяет типы ответов, границы шкал, критерии, точные цитаты и диапазоны. При некорректном ответе выполняется ограниченный повтор; сбой остаётся видимым. Структурированный формат сам по себе не гарантирует верную смысловую оценку.

Адаптер анализирует текст. Критерии, требующие прослушивания аудио, получают needs_review; наличие плеера не означает, что модель прослушала запись. Для отдельной оценки дикции или интонации потребуется аудиоадаптер и явные правила такой проверки.

Стоимость считается по настроенным тарифам в USD за миллион токенов: `LLM_INPUT_COST_PER_MILLION`, `LLM_OUTPUT_COST_PER_MILLION`, `LLM_CACHED_INPUT_COST_PER_MILLION`, `LLM_CACHE_WRITE_INPUT_COST_PER_MILLION`. Без необходимых тарифов или usage полная стоимость неизвестна. Для OpenAI запрашивается стандартный `service_tier=default`; возвращённый тариф проверяется, а при неизвестном или другом тарифе стоимость остаётся неизвестной. Сохраняются фактическая модель, попытки, входные, выходные, reasoning/cache-токены и время; известный подытог не выдаётся за полную стоимость. [Сравнение моделей](evaluation/BENCHMARK.md) ведёт отдельный журнал бюджета и возобновляемые результаты.

## Данные и контрольный набор

Формат файла: DatasetExport с полями isSuccess, error, data.dataset_group_id, data.total_records, data.records. [Синтетический пример](fixtures/synthetic_dev.json). Диалог содержит conversation_id, language, channel, transcript, опционально audio_url. В реплике — timestamp, speaker, text.

Ключ диалога состоит из группы и ID. Повторный импорт не создаёт дублей. Изменение исходника не переписывает снимки прошлых оценок.

Реальный DEV находится локально в `data/raw/DEV.json` и не включается в Git. Для повторного получения задайте CQA_DEV_URL из исходного задания:

```powershell
.\.venv\Scripts\python.exe scripts/fetch_dataset.py --group DEV
```

Для контроля используйте объявленный организаторами group_id. Сохранённый JSON загружается через тот же интерфейс. Подписанные ссылки, ключи, настоящие транскрипты и runtime-БД не публикуются.

## Проверка и разработка

[Реальное сравнение Luna и Luna + Sol](docs/HYBRID_PILOT.md): 24 новых синтетических чата, 188/192 против 190/192 совпадений с авторской разметкой, расходы $0.036 против $0.399. Прирост недостаточен для автоматического включения Sol; рабочий профиль остаётся Luna. [Проверка GPT-Transcribe и подготовка FreedomSpeech](docs/ASR_PILOT.md) выполняются отдельно от официальных оценок.

[Выполненные прогоны со сбоями и пограничными случаями](docs/FAULT_REHEARSAL.md):
166 backend-тестов, 15 браузерных сценариев, реальный HTTP с перезапуском
тестового процесса и 12 новых синтетических диалогов через Luna. Здесь же
сохранены команды повторения, найденные дефекты, результаты и ограничения.
Очередь оценки теперь можно продолжить после потери ответа или обновления
вкладки; принятые задачи проверяются по сохранённым ключам.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s backend/tests -v
npm --prefix frontend run build
```

Тесты используют изолированные тестовые ответы, не платные модели. Они проверяют механику, а не точность AI. Инструменты разметки и сравнения результатов находятся в [evaluation/](evaluation/). Результаты и повторение сквозного браузерного сценария — в [отчёте проверки](docs/VALIDATION.md).

Для разработки запустите в двух терминалах:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.cqa.main:app --host 127.0.0.1 --port 8000 --reload
npm --prefix frontend run dev
```

Vite перенаправляет /api на FastAPI. Собранное приложение обслуживает один сервер. [OpenAPI](http://127.0.0.1:8000/docs), [API-контракт](docs/API_CONTRACT.md), [расчёт](docs/SCORING.md).

## Подготовка к отбору

[Проверка готовности и оставшиеся риски](docs/READINESS_AUDIT.md): репетиция на десяти новых чатах, работа звонков, изменения критериев, апелляции и корректность сдачи. [Воспроизводимые наборы и команды](fixtures/readiness/README.md) отделяют синтетические проверки от официального Ground Truth.

[Оперативная памятка SetW](docs/HACKATHON_BRIEF.md): дедлайн **8 ноября, 12:00 по Астане**, час на контроль и push, обязательный публичный GitHub, сценарий живой защиты и уточнения из обеих Q&A. Подробные источники и спорные формулировки сохранены отдельно; требования к JSON и шкалам не изменены.

Основной ориентир топ-50 — близость к Ground Truth по критериям на десяти неизвестных **чатах**. Внутренняя формула отбора не раскрыта; также учитываются работающий процесс, удобство и технический подход. [Уточнения Nikolay Borovinskiy и других ответов](docs/ORGANIZER_CLARIFICATIONS.md) сохранены с датами и ID сообщений. Чек-лист и арифметика теперь проверены; качество AI ещё требует независимой разметки по языкам и критериям. Учебные метки и согласие моделей между собой не являются Ground Truth организаторов.

[Приложение к гайду](docs/briefs/CQA_Student_Guide_Appendix_Results.pdf) задаёт `results/dev/results.json` для 60 чатов и 5 звонков и `results/prod/results.json` для 10 контрольных чатов. Успешная запись содержит все восемь критериев, краткие обоснования, номера исходных реплик от 1, итог и отдельный `critical_flag`. Необработанный диалог сохраняет свой ID и `status="error"`; N/A не заменяет ошибку. В интерфейсе кнопка «Файл для сдачи» открывает форму команды, набора, DEV/PROD и модели; она выгружает всю группу независимо от фильтров списка и показывает количество успешных записей и ошибок. Для командной строки: `python -m evaluation.submission --help`.

В приложении требуется commit и push результатов в открытый репозиторий до стоп-кода. Текущая работа сама по себе не меняет видимость репозитория и не публикует результаты; публикация выполняется отдельно в согласованном объёме. Исходные транскрипты, ключи, подписанные ссылки и runtime-БД остаются локальными.

Защита: новый файл → оценка → доказательство → апелляция → новый итог → изменение критерия и повторная проверка. Сроки T+23/T+24 и пятиминутная защита описаны в [задании](docs/briefs/CQA_Student_Guide.pdf). Точный T0 сверяется с организаторами.
