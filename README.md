# SetW

**CQA для Freedom Broker:** загрузите переписку на русском, казахском или английском, получите оценку по восьми критериям и проверьте каждое решение по исходным репликам. Специалист качества может пересмотреть спорный ответ, сохранить основание и увидеть новый итог вместе с историей изменений.

Приложение работает локально. React и TypeScript отвечают за интерфейс, FastAPI за API и проверку ответов, SQLite за данные и историю. Для AI-оценки используется подключённая модель через OpenAI Responses API или совместимый Chat Completions API.

## Возможности

- Импорт JSON организаторов с сохранением языка, ролей, временных меток и исходных ID; фильтры по набору, языку, каналу и грубым ошибкам.
- Оценка одного диалога или выборки, состояния задач, ошибки и продолжение очереди после обновления вкладки.
- Восемь критериев, объяснения, точные цитаты с переходом к реплике и диапазоны проверки отсутствующих действий.
- Редактирование критериев, весов, шкал и применимости с сохранением новой версии чек-листа и повторной оценкой.
- Апелляции с обоснованием решения, пересчётом итога и сохранением первоначального ответа модели.
- Сводка по критериям, история оценок, аудиоплеер при доступной записи и отдельный экспорт для сдачи в JSON 1.0.

## Быстрый запуск

Нужны **Python 3.13** и **Node.js 24**. Команды выполняются из корня репозитория. Интернет нужен для первой установки зависимостей и обращений к внешней модели.

**Windows, PowerShell:**

```powershell
.\scripts\start.ps1 -Setup
```

Скрипт создаст `.venv`, установит зависимости, создаст `.env` из примера при его отсутствии, соберёт интерфейс и запустит сервер. Следующий запуск: `.\scripts\start.ps1`; пересборка: `.\scripts\start.ps1 -Build`; другой порт: `-Port 8001`.

**Linux или macOS:**

```bash
python3.13 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
test -f .env || cp .env.example .env
npm --prefix frontend ci
.venv/bin/python scripts/run.py --build
```

Откройте [приложение](http://127.0.0.1:8000) или [OpenAPI](http://127.0.0.1:8000/docs). Остановка: Ctrl+C. Повторный запуск на Linux/macOS: `.venv/bin/python scripts/run.py`. База и история сохраняются в `data/runtime/cqa.sqlite3`.

Без подключения модели доступны импорт, просмотр, настройка чек-листа и история. Для знакомства загрузите [синтетический пример](fixtures/synthetic_dev.json); учебные данные явно отделены от реальных результатов.

## Подключение модели

Для профиля опубликованного прогона заполните локальный `.env` и перезапустите сервер:

```dotenv
LLM_BASE_URL=https://api.openai.com/v1
LLM_API_STYLE=responses
LLM_MODEL=gpt-6-luna
LLM_API_KEY=your-api-key
LLM_REASONING_EFFORT=high
LLM_JSON_MODE=json_schema
LLM_MAX_TOKENS=16384
LLM_TIMEOUT_SECONDS=180
LLM_CONCURRENCY=2
```

`your-api-key` замените своим ключом. Он хранится на сервере, в браузер не передаётся. `.env`, исходные клиентские записи и runtime-база исключены из Git. Полный текст выбранного диалога отправляется провайдеру при запуске оценки. Текущие модель и версия промпта видны в интерфейсе и `/api/config`.

Для другого сервера задайте его адрес и модель, `LLM_API_STYLE=chat_completions` и поддерживаемый `LLM_JSON_MODE`: `json_object`, `json_schema` или `none`. Неиспользуемый `LLM_REASONING_EFFORT` оставьте пустым. Локальный сервер без авторизации допускает пустой ключ. Все настройки и необязательные тарифы для расчёта стоимости перечислены в [.env.example](.env.example).

## Сценарий проверки продукта

1. Импортируйте исходный JSON, выберите набор и диалог.
2. Запустите оценку по официальному чек-листу и откройте доказательства по критерию.
3. Проверьте переход к реплике и отдельный флаг грубой ошибки.
4. Подайте апелляцию, примите решение с основанием и сравните исходный и новый итог.
5. Сохраните новую версию критерия и повторно оцените диалог; прежний снимок останется в истории.
6. Откройте «Файл для сдачи», выберите группу, DEV/PROD, команду и модель. Экспорт охватывает всю группу независимо от фильтров списка.

Исторический экспорт приложения и официальный JSON 1.0 имеют разные назначения. Файл для сдачи берёт исходные ответы модели по утверждённому чек-листу; апелляции и произвольные изменения весов их не подменяют. [API-контракт](docs/API_CONTRACT.md).

## Как получается оценка

```text
Исходный JSON -> нормализация -> диалог + версия чек-листа -> LLM
Ответ LLM -> проверка схемы и цитат -> расчёт баллов -> SQLite -> интерфейс
```

Модель определяет применимость, ответ и доказательства. Сервер проверяет состав критериев, типы, разрешённые ступени, дословность цитат и порядок диапазонов, затем самостоятельно считает итог. Некорректный ответ допускает ограниченный повтор; неустранённая ошибка остаётся видимой.

[Официальный чек-лист](docs/briefs/CQA_Chat_Quality_Checklist.pdf) и его [машинная конфигурация](fixtures/checklist.official.json) задают веса **10 / 15 / 20 / 20 / 15 / 15 / 5 / 0**. N/A исключается из применимого веса, шкалы нормализуются, итог округляется до двух знаков. Грубая ошибка отмечается отдельно и не обнуляет балл. `needs_review` означает незавершённую проверку и не превращается в N/A или ноль. [Формула и примеры](docs/SCORING.md).

## Проверки и воспроизведение

После установки активируйте окружение: `.\.venv\Scripts\Activate.ps1` на Windows или `source .venv/bin/activate` на Linux/macOS. Затем:

```bash
python -m pip check
python -m unittest discover -s backend/tests -v
npm --prefix frontend run build
```

Эти проверки не вызывают платные модели. Они проверяют контракты, расчёт, хранение, API и сборку интерфейса; смысловая точность AI оценивается отдельно. Те же основные команды выполняются в [GitHub Actions](.github/workflows/checks.yml). Сценарии браузерной проверки и работы со сбоями: [VALIDATION](docs/VALIDATION.md), [FAULT_REHEARSAL](docs/FAULT_REHEARSAL.md).

При наличии локальных исходников организаторов можно проверить состав, ID, доказательства и формат файлов сдачи:

```bash
python -m evaluation.submission validate --dataset data/raw/DEV.json --split dev --input results/dev/results.json
python -m evaluation.submission validate --dataset data/raw/FBroker.json --split prod --input results/prod/results.json
```

Исходники организаторов не входят в репозиторий. Укажите фактический путь к полученному JSON. Проверка и экспорт сохранённых оценок не вызывают модель; параметры экспорта доступны через `python -m evaluation.submission export --help`.

## Границы решения

Это локальное приложение с одним процессом API и SQLite. Авторизация пользователей и распределённая очередь не реализованы. Модель работает по тексту: аудиоплеер позволяет человеку слушать запись, но не означает, что AI обработал звук. Критерии, требующие аудио, остаются на проверке.

Точные цитаты и валидный JSON подтверждают связь результата с исходником, но не гарантируют правильную интерпретацию. Официальный GT недоступен; авторская разметка и согласие разных моделей его не заменяют. Стоимость является оценкой по usage и заданным тарифам, а при неполных данных остаётся неизвестной. Повторный вызов модели может дать иной ответ; сохранённые снимки позволяют проверить конкретный прогон. [Сравнение моделей](docs/BENCHMARK_RESULTS.md) и [уточнения организаторов](docs/ORGANIZER_CLARIFICATIONS.md).
