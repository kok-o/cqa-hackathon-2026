# Контроль SetW · 8 ноября, 11:00–12:00 UTC+5

Организаторы выдали `FBroker`: десять контрольных чатов. Дополнительный `Swap`
содержит три записи и сохраняется отдельно до следующей инструкции. Для PROD
используется только FBroker и официальный чек-лист из восьми критериев.
Ни исходные данные, ни подписанная ссылка не включаются в Git.

## Подготовленный запуск

`scripts/start-control.ps1` запускает приложение на `http://127.0.0.1:8061`
с отдельной базой `data/runtime/control-20261108.sqlite3`. DEV остаётся в своей
базе. Повторный старт требует `-Resume`, чтобы явно продолжить существующую
работу. Ключи берутся из локального `.env`; в вывод они не попадают.

```powershell
# Из корня проекта; этот процесс должен продолжать работать.
.\scripts\start-control.ps1 -Build
# После остановки для продолжения: .\scripts\start-control.ps1 -Resume
```

Если код открыт в отдельном worktree, укажите `-RuntimeRoot` с путём основного
проекта, где находятся `.venv` и `.env`. Этот параметр поддерживает также
`scripts/control.ps1`. В интерфейсе контроля должна быть модель Luna/high,
актуальная версия промпта и официальный чек-лист. Новая база до импорта пуста.

## Получение и один запуск

Ссылки организаторов работают через GET. Настроенный локальный `CQA_DEV_URL`
используется скриптом без вывода подписи. Имена групп подтверждены объявлением.

```powershell
.\.venv\Scripts\python.exe scripts/fetch_dataset.py --group FBroker
.\.venv\Scripts\python.exe scripts/fetch_dataset.py --group Swap

# Только проверка формата и подключения; без импорта и вызовов AI.
.\scripts\control.ps1 -Dataset .\data\raw\FBroker.json -CheckOnly

# Реальная оценка через HTTP API приложения и проверка сохранённого результата.
.\scripts\control.ps1 -Dataset .\data\raw\FBroker.json

# Та же команда продолжит задания и затем отправит результат в main.
.\scripts\control.ps1 -Dataset .\data\raw\FBroker.json -Publish
```

Повтор команды использует сохранённые задания и ключи идемпотентности.
Одновременно идут не более двух заданий. Новые попытки для технически
неудавшихся заданий включаются явно параметром `-RetryFailed`. Полная оценка,
оставшаяся неопределённой по смыслу, не заменяется выдуманным ответом.

Исходный файл, версия промпта, конфигурация модели и чек-лист связаны с состоянием
`data/runtime/control-run/state.json`. При несовпадении продолжение блокируется.
Промежуточный результат сохраняется рядом в `results.json`. Тестовый режим
отделён в `data/runtime/rehearsal` и не допускается к публикации.

## Проверка и Git

Проверяются десять уникальных исходных ID, отсутствие звонков, восемь критериев,
шкалы, арифметика, ссылки на реплики, команда SetW и модель. Экспорт сверяется с
конкретными заданиями этого запуска. Ошибки остаются строками `status=error`.
Если после разбора необходимо сдать неполный файл, отдельно запустите
`control_publish.py --allow-errors` с проверенными исходником и результатом.
Общая команда при любой ошибке запуска останавливается и ничего не публикует.

Публикация требует чистое дерево и подготовленный код уже в `origin/main`.
Коммит содержит только `results/prod/results.json`; существующий файл сначала
сохраняется в игнорируемую резервную копию. После обычного push проверяются SHA
ветки и blob результата. При сетевом сбое push можно повторить без нового
модельного вызова. После 12:00 UTC+5 скрипт не создаёт коммит и не выполняет push.

```powershell
# Отдельная публикация уже подготовленного файла без оценки:
.\.venv\Scripts\python.exe scripts/control_publish.py --dataset data/raw/FBroker.json --input data/runtime/control-run/results.json --publish
```

Репозиторий по последнему решению владельца остаётся **закрытым**. Это не меняет
правильность JSON и push, но не выполняет требование организаторов о публичном
доступе. Передача ссылки через объявленный канал также является отдельным шагом.
