## Изолированный запуск

Для проверки используйте учебные данные и отдельную временную SQLite-базу. Никакие модельные сервисы не нужны. В корне проекта:

```sh
npm --prefix frontend run typecheck
npm --prefix frontend run build
CQA_BROWSER_TEST=1 CQA_BROWSER_TEST_DB=/tmp/cqa-frontend-qa.sqlite3 \
  .venv/bin/python -m uvicorn backend.tests.browser_fixture:create_browser_app \
  --factory --host 127.0.0.1 --port 8001
```

Для повторного чистого прогона укажите новое имя базы. Тестовое приложение использует `checklist.example.json` и явно сообщает `mode=test`; это проверка механики интерфейса, не качества AI.

В отдельном терминале, где установлены Playwright и Chrome/Chromium:

```sh
.venv/bin/python scripts/browser_smoke.py --url http://127.0.0.1:8001
.venv/bin/python scripts/frontend_review_smoke.py --url http://127.0.0.1:8001
```

Оба скрипта отказываются изменять сервер без `mode=test` и проверяют адрес localhost. Результаты и учебные снимки сохраняются в игнорируемой папке `scratch/`. Скрипты не являются доказательством прохождения до успешного завершения; результат записывается только после всех проверок.

## Ручной контроль

- На 1024 px открыть и закрыть очередь, затем вернуться к текущему диалогу.
- Tab/Shift+Tab/Enter: импорт, фильтры, диалог, критерий, доказательство, апелляция. Фокус виден и не попадает в скрытые панели.
- Escape закрывает открытые фильтры и формы; фокус возвращается к вызвавшей кнопке.
- Повторить переход по доказательству после прокрутки длинного диалога. Возврат сохраняет выбранный критерий и позицию результатов.
- Включить системное уменьшение движения: смена панелей мгновенна, подсветка и фокус сохраняются.
- Проверить состояния API: нет модели, queued, running, completed, failed, повтор после сбоя и фактический пакетный прогресс.
- Проверить N/A с причиной, `needs_review` без выдуманного итога, отдельную метку грубой ошибки, исходную и пересчитанную оценки.
- По официальному чек-листу проверить дискретные ступени консультации и ведения диалога. Учебная схема не заменяет эту проверку.
- «Файл для сдачи» сверять с приложением к гайду: 65 DEV или 10 PROD; все исходные ID учтены, ошибки — `status=error`, исходные AI-ответы сохраняются до апелляций. Это отдельный формат от экспорта истории.

## Демонстрация за пять минут

1. **1 минута:** импорт учебного набора, очередь и выбранный диалог.
2. **2 минуты:** итог и версия правил, критерий, цитата и проверенный диапазон, причина N/A.
3. **1 минута:** апелляция, обязательная причина решения, исходный и новый итоги.
4. **1 минута:** изменение критерия, новая версия, повторный запуск и доступность прошлой оценки.

Учебный режим и ранее рассчитанный результат должны быть подписаны на экране. Синтетические ответы подтверждают работу интерфейса; официальную точность проверяют отдельно по Ground Truth.
