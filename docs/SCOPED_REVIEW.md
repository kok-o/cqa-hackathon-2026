8 ноября до стоп-кода команда запросила исправление двух отмеченных случаев.
Вместо повторной оценки всех критериев использованы два слепых запроса
Luna/high/v11: полный исходный диалог, полный официальный чек-лист как контекст,
но только выбранный критерий в выходной схеме. Предыдущие оценки и желаемые
ответы модели не передавались. Повторного выбора между несколькими ответами
одной модели не было.

| Диалог и критерий | Исходная оценка | Независимая Luna | Принятое изменение |
|---|---|---|---|
| p2-ru-002, C2 | Нет | Нет | Значение сохранено, разногласие с Sol остаётся |
| p2-kz-001, C6 | 10 | 7 | Применено 7; итог 88,13 |

Результат C6 подтверждён отсутствием предупреждения при зафиксированной
проверке во время работы оператора. Продолжительность паузы не используется
как выдуманный SLA. Объяснения на русском, цитаты дословны. Два ответа
применены целиком, без редактирования значений и обоснований. 78 невыбранных
решений сохранены побайтно как JSON-объекты; всего изменилось одно из 80 значений.

Исходные десять вызовов стоили $0.02277498, две перепроверки $0.00257541.
Итого $0.02535039, среднее $0.002535039 за чат. Обе стадии используют
`gpt-6-luna`; в локальном model_info сохраняются отдельные usage, ответы,
снимки источника и чек-листа. Перепроверенные записи имеют pipeline
`selective-independent-review-v1` и версию `cqa-evaluator-v11+scoped-review-v1`.
Восемь остальных записей сохраняют исходную версию. Это проверка по запросу
специалиста, а не автоматически включённая маршрутизация всех новых чатов.

## Повторение процесса на своих данных

`source.json` содержит список полных внутренних записей приложения.
`plan.json` задаёт группы, ID и критерии для проверки, без готовых оценок:

```json
[{"group_id":"YOUR_GROUP","conversation_id":"YOUR_ID","criterion_ids":["dialogue"]}]
```

```powershell
python scripts/review_criteria.py --source source.json --plan plan.json --out reviews.json
python scripts/merge_scoped_review.py --source source.json --reviews reviews.json --out predictions.json
python scripts/import_benchmark.py --predictions predictions.json --database data/runtime/review.sqlite3 --dry-run
python scripts/import_benchmark.py --predictions predictions.json --database data/runtime/review.sqlite3
```

До импорта результатов исходный набор и официальный чек-лист должны быть
загружены в выбранную базу через приложение. Затем приложение экспортирует
всю группу стандартным `/api/submission/export`; формат и покрытие проверяются
обычным валидатором. В этом запуске использована отдельная локальная база
`data/runtime/control-scoped-20261108.sqlite3`, интерфейс на порту 8065.
Экспорт приложения сопоставлен со всеми десятью сохранёнными записями.

Скрипт объединения проверяет одинаковую модель, хеши источника и чек-листа,
точный request hash при наличии, исходные результаты, цитаты, шкалы и итог.
Он отвергает неопределённые ответы и не меняет входные файлы. Официальный
Ground Truth недоступен, поэтому оставшееся разногласие C2 не скрывается.

Шесть отдельных тестов проверяют сохранность невыбранных критериев,
модель, хеши и идентичность снимков. Полный набор из 244 тестов прошёл.
Финальная проверка экспорта: 10 `ok`, 0 `error`, 0 предупреждений.
