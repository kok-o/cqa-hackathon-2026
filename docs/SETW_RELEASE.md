## Изменение в приложении

Фильтр «Без грубых» исключает оценки с неразрешённым критерием, который может установить грубое нарушение. Подтверждённый флаг отображается даже при неполноте другого критерия. После пересмотра результат фильтра пересчитывается по текущей оценке, история сохраняет исходную. Регрессионный тест сначала воспроизвёл ошибку, затем подтвердил исправление.

Вкладка «Сводка» показывает частые снижения по применимым критериям, число затронутых диалогов и грубые нарушения отдельно. Она использует последние оценки совпадающего снимка диалога по выбранной версии чек-листа и учитывает решения по апелляциям. Неполные и отсутствующие оценки показаны раздельно. Нажатие на диалог открывает нужную оценку и критерий, откуда можно перейти к реплике или проверенному диапазону. Запрос к провайдеру не требуется.

## Исходный набор и разбор

- DEV содержит 60 чатов и 5 транскриптов звонков. В приложении сохранены 137 завершённых оценок двух моделей. Для текущего DEV выбраны 65 оценок Luna, из них 57 на v5 и 8 на v6. Воспроизведённый экспорт по исходным ID совпал с `results/dev/results.json`. 65 `ok`, 0 `error`. Оставшиеся 11 предупреждений относятся к N/A без номера подтверждающей реплики.
- Проверены все 36 различий между сохранёнными решениями Luna и Sol/v3 на 22 диалогах. Разметка ассистента по доступному источнику выделила 7 ошибок, 27 допустимых трактовок и 2 случая с недостаточным контекстом. Для звонков разбирался текст. Правила, номера реплик и обоснования каждой строки сохранены локально.
- Проверены восемь совпавших решений в каждом из шести чатов, по два чата на язык. В одном случае значение C2 подтверждается, но обоснование игнорирует уже названный клиентом тип ошибки. Некоторые баллы C4 и C7 допускают две трактовки даже при совпадении моделей.
- Для независимой ручной проверки подготовлены 15 чатов, по пять на RU, KZ и EN. Пакет первого прохода содержит источник и бланк. Модельные ответы находятся в отдельном файле для второго прохода.

Главные проверенные гипотезы касаются C2 при уже известных деталях, C5 для нейтрального запроса, C4 при отдельном флаге C8 и порядка проверки личности. C6 отделяет ясность от неполноты консультации. Для C7 отсутствие ответа клиента само по себе не подтверждает обрыв. [Официальный чек-лист](briefs/CQA_Chat_Quality_Checklist.pdf)

## Каскад

Luna оценивает диалог, селектор передаёт Sol только критерии, требующие повторного рассмотрения. Sol получает исходный диалог и правила для независимой проверки. При сбое сохраняется результат Luna с указанием причины.

В первом пилоте на 24 чатах Sol пересмотрел 25 критериев в 12 чатах. Два результата C5 совпали с замороженными ожиданиями после пересмотра, новых несовпадений не наблюдалось. Одно исходное расхождение C5 маршрутизатор пропустил, другое осталось после проверки. Один из двух исправленных ответов и один остаточный случай допускают разную трактовку правила. Стоимость по usage выросла с $0.03609 до $0.39945, доплата $0.36336 за 24 чата. Время по сумме запросов выросло в среднем с 20,04 до 34,61 с, p95 с 34,30 до 94,71 с. Решение о включении учитывает устойчивость выигрыша и абсолютную доплату. [Первый пилот](HYBRID_PILOT.md) · [разбор его ошибок](validation/hybrid-pilot/error-analysis.json)

Для нового сравнения правила отбора выведены из прежнего пилота и известных DEV. Экспериментальный селектор сохраняет перепроверку `needs_review`, риск C3/C8 и отрицательную C5. Он дополнительно ищет положительную C5 при явном затруднении и слабой консультации или ведении, положительную C2 без видимого запроса на уточнение и низкую C4 при грубом нарушении. Промежуточная ступень C4 или C6 сама по себе пересмотр не запускает. На одинаковых 12 новых чатах, по четыре на язык, сравниваются сохранённые Luna/high/v6, полный Sol/high/v6 и каскад с независимой проверкой выбранных критериев Sol/high/v6. Эвристики для маршрута и ожидания зафиксированы заранее. Ограниченная синтетика проверяет отбор и стоимость. Перенос на реальный поток потребует независимой разметки.

На проверочных ответах у Luna не было несовпадений, которые Sol мог бы исправить. Каскад перепроверил 17 из 96 критериев и сохранил их решения. Полный Sol изменил три незамороженные трактовки. Он оставил C3 на проверке при потере сообщений оператора, отделил C6 от частного платного предложения и по-другому трактовал вежливость при навязывании платной помощи. Эти изменения не включены в счётчик качества. В диалоге без реплик оператора у всех трёх путей сохранился неполный итог.

На старом наборе, использованном для настройки, v2 выбрал бы 10 чатов и 20 критериев вместо 12 и 25. Он охватил бы 4 из 4 исходных несовпадений вместо 3 из 4, включая пропущенную C5 при противоречивой реакции на явное затруднение. Это перепроверка маршрута по сохранённым ответам Luna. В свежих 12 чатах v1 выбрал бы 8 чатов и 19 критериев. В дополнительной проверке по уже сохранённым ответам на остальных новых чатах v2 пропустил C6 при ожидании после первой реплики оператора. Sol для этого случая не вызывался, поэтому эффект пересмотра неизвестен.

Доплата каскада составила $0.10012 за 12 чатов, около $0.00834 на чат. В этой выборке экономия относительно полного Sol не сопровождалась измеренным улучшением над Luna. Каскад остаётся воспроизводимым экспериментом. Для следующей проверки нужна свежая независимая разметка, включая подтверждённые ошибки и пограничные случаи. LoRA остаётся возможным направлением после получения подходящего корпуса и разметки.

Суммарно за ночь 234 запроса к API, $0.84373935 по usage и 0 запросов с неизвестной стоимостью. Сюда входят оба плеча Luna, 12 полных и 6 выборочных запросов Sol. Сохранённая Luna для каскада учтена один раз. Длительность каскада рассчитана суммой запросов на чат без очереди между стадиями.

- Исходный backend 209 тестов, после исправления и сводки 211. Проверены `pip check`, TypeScript и Vite. GitHub приватный по данным `gh repo view`.
- Семь проверок с локальным HTTP и внедрёнными ошибками. Проверены потеря ответа, идемпотентность, позднее завершение старого снимка, актуальность выгрузки, конфликт апелляций, перезапуск и ограниченные повторы запроса.

Основной путь включает импорт, job, переход к доказательству, сводку, апелляцию, пересчёт, новую версию критерия, повторную оценку и экспорт. Браузер использовал механический тестовый ответ. На копии сохранённого DEV открыты три демонстрационных примера и выделены их доказательства.
- Десять новых синтетических чатов получили живые ответы Luna в каждом плече сравнения. Затем оба набора ответов по отдельности прошли через FastAPI и изолированную SQLite. Репетиционный экспорт помечен `SYNTHETIC-READINESS-NOT-FOR-SUBMISSION` и хранится локально. Повторное проигрывание ответов не обращалось к провайдеру.
- Рабочая БД и исходный DEV имеют контрольные суммы. SQLite-снимок прошёл `integrity_check` и сохранён отдельно. В проверенном дереве отсутствуют отслеживаемые пути к raw/runtime/evaluations и совпадения с локальными ключами и подписью URL. Проверены активные URL в трёх PDF.
