# Работа трёх участников

Распределение принято как стартовое. Нурхан — владелец репозитория `kok-o`. Приглашения участникам отправляет владелец.

## Нурхан — AI и проверка качества

Владение — `backend/cqa/evaluator/`, `prompts/`, `evaluation/`.

1. Проверить официальный чек-лист вместе с Нариманом.
2. Разметить представительный набор диалогов. Для каждого критерия сохранить ожидаемый ответ, основание, ID реплик и допустимое расхождение.
3. Провести короткое сравнение доступных моделей на одинаковых примерах. Зафиксировать название, стоимость одного полного вызова оценки, p50/p95, ошибки по языкам.
4. Реализовать `evaluate(conversation, checklist_version)` с выходом `EvaluationDraft`.
5. Формировать запрос из актуальной версии чек-листа. Передавать роли и стабильные ID реплик.
6. Проверять схему, диапазоны, существование evidence-ID и соответствие цитаты оригиналу.
7. Для отсутствующего действия возвращать проверенный диапазон. Для N/A давать причину. Для непроверяемого критерия использовать `needs_review`.
8. Если критерии требуют дикцию/интонацию, согласовать обработку аудио и время фрагментов. Сохранить транскриптный маршрут для остальных критериев.
9. Ограничить повторы, записывать число вызовов, usage, время, модель и версию инструкции.
10. Проверить изменённый и добавленный через UI критерий на новых диалогах.

Передать Нариману функцию оценки, валидируемый результат и ошибки. Передать Олжасу примеры обычной оценки, пропущенного действия, N/A и `needs_review`.

Готовность — ответы воспроизводимы на зафиксированном наборе, доказательства доступны, новый критерий обрабатывается через конфигурацию.

## Нариман — сервер, данные, баллы и интеграция

Владение — `backend/cqa/` кроме `evaluator/`, `scripts/`, `contracts/`, миграции и сборка.

1. Импортировать официальный JSON и сохранить исходный файл локально.
2. Нормализовать диалоги, присвоить стабильные ID реплик, сохранить исходные timestamps.
3. Реализовать SQLite-схему и транзакции. Включить foreign keys, WAL и ограничение времени ожидания блокировки.
4. Реализовать чтение диалогов, создание и чтение версий чек-листа.
5. Сделать задачи оценки со статусами `queued/running/completed/failed`, привязкой к версии и понятными ошибками.
6. Подключить evaluator Нурхана. Не держать SQL-транзакцию открытой во время вызова модели.
7. Реализовать официальный расчёт баллов как отдельную чистую функцию и тесты из SCORING.md.
8. Реализовать апелляцию и решение проверяющего с ревизией состояния. Сохранение решения и пересчёт финала выполняются одной транзакцией.
9. Сделать идемпотентное сохранение и конфликт `409` при устаревшей ревизии.
10. Подготовить единый запуск, сборку интерфейса, инструкции и фиксацию финального SHA.

Передать Олжасу реальные endpoints с OpenAPI и понятными ошибками. Все изменения контракта объявлять до merge.

Готовность — импорт повторяем, данные переживают перезапуск, суммы проверены вручную, апелляция сохраняет историю.

## Олжас — интерфейс и демонстрация

Владение — `frontend/`, кроме совместно согласуемых типов контракта.

1. Создать React/TypeScript/Vite-приложение. Начать с синтетического ответа API.
2. Сделать список диалогов с языком, каналом и состоянием проверки.
3. Сделать транскрипт с ролями, исходным временем и якорем каждой реплики.
4. Сделать редактор чек-листа с весом, типом, шкалой, N/A, названием и инструкцией критерия.
5. Сохранять новую версию и явно показывать, какая версия выбрана для оценки.
6. Реализовать запуск, прогресс, ошибку и повтор. При смене диалога показывать результат выбранного запуска.
7. Показать ответы, баллы, доказательства, проверенный участок, N/A, грубую ошибку и итоги секций.
8. Реализовать переход к реплике и воспроизведение аудио при доступном источнике.
9. Реализовать форму апелляции и отдельное действие проверяющего с причиной и сравнением старого/нового результата.
10. Подготовить сценарий нового критерия, длинные тексты, RU/KZ/EN, пустые состояния и пятиминутное демо.

Передать Нариману список требуемых полей до подключения реальных endpoints.

Готовность — весь сценарий доступен мышью и клавиатурой, видно состояние запроса, доказательства открываются, новый критерий сохраняется и применяется.
