# Проверка решения SetW

Проверено 7 ноября 2026 года на Windows, Python 3.13 и Node.js 24.

## Механика приложения

- 127 автоматических тестов API, расчёта, OpenAI Responses, импорта результатов,
  экспорта JSON 1.0 и сравнительных запусков проходят. Тесты изолированы от платных API.
- `pip check`: конфликтов зависимостей нет. `npm --prefix frontend run build`:
  TypeScript и production-сборка проходят.
- Объединены изменения интерфейса из `origin/main` (`7c0697e`): обозначение
  тестового режима, обработка конфликта апелляций и отсутствие аудио у звонка.
- Семь сквозных браузерных проверок прошли на отдельной тестовой базе:
  импорт, задача оценки, переход к доказательству, апелляция с сохранением оригинала,
  новый критерий/версия, ранее неизвестный JSON и скачивание истории. Ошибок JS нет.
- Дополнительно проверены шесть сценариев официального чек-листа и шесть
  сценариев файла сдачи: SetW, полный набор независимо от фильтров, ошибка 422,
  выбор DEV/PROD, скачивание и режим локальной модели. Эти сценарии используют
  явно тестовые ответы и не доказывают качество AI.
- Реальный сервер проверен отдельно: OpenAI Luna/high/v6 настроен, официальный
  чек-лист содержит восемь критериев, все 65 диалогов имеют итоговую оценку.
  История различает Luna и Sol по названиям. Скачанный через интерфейс файл
  полностью совпадает с `results/dev/results.json`: SetW, Luna, 65 `ok`.
  На 1440×1000 и 390×844 нет ошибок JavaScript и горизонтального переполнения.
- Пакетный перенос сохранённых результатов в SQLite не вызывает модель повторно,
  сохраняет исходные решения, допускает повторный импорт без дублей и не меняет апелляции.

GitHub Actions для `b536e81` также завершился успешно: серверные тесты и frontend build.

## Реальные вызовы

Завершена отдельная синтетическая регрессия: 6 диалогов × 3 модели на `max`.
У каждой модели 48/48 совпадений с авторскими проверочными ответами. Это не GT
организаторов и не независимая экспертная оценка точности.

Полный Sol/max/v3: 65/65 успешных оценок, один повтор, расчёт $4,72134970.
Первый полный Luna/high/v5: 64/65, один неуспешный звонок и один повтор,
$0,15206649. Адресный Luna/high/v6: 19/19 без повторов, включая восемь DEV
и 11 синтетических примеров. На последних прошли 48 исходных, 24 tuning,
8 queue и 1 speculation авторских проверок. Эти примеры использовались при
разработке промпта; результат 81/81 не является независимой оценкой точности.

`results/dev/results.json` содержит SetW, 65 `ok`, 0 `error`: 57 ответов v5
и восемь обновлений v6. Проверены покрытие исходных ID, все критерии и арифметика.
Валидатор сообщает 11 предупреждений о пустых `evidence_turns`; все относятся
к N/A, где `value=null`, и не заменены выдуманными доказательствами.
Экспорт API и скачанный через интерфейс файл совпадают полностью. В SQLite
сохранены исходные оценки обеих моделей и история обновлений; синтетические
проверочные случаи в рабочую базу не импортировались.

Расчёт на получение итогового DEV — $0,17874552, включая все 74 API-попытки
для 73 оценок (неуспешная и заменённые ответы включены). Разработческие пилоты
учтены отдельно. Это смешанный набор v5/v6, а не полный чистый прогон v6.
С Sol совпали 484/520 решений; это согласие, а не доказанная правильность.
Sol сохранён в `results/reference/sol-dev-v3.json`, он не является GT.
Сравнение моделей и все ограничения — в [отчёте](BENCHMARK_RESULTS.md).

Рабочая Luna использует `high`, 16384 токена и 180 секунд; новый промпт — v6.
Ранние пилоты `max` сохранены отдельно. Новых вызовов Astra после решения
прекратить её проверку не было. Дорогой профиль Sol включается только вручную.
Адаптер явно запрашивает стандартный service tier и проверяет возвращённое
значение. В ранних max-пилотах тариф не фиксировался, поэтому их стоимость
представлена только как оценка по стандартным ставкам, не как счёт провайдера.

Ошибка ответа теперь сохраняет безопасный код и проверенные идентификаторы;
ограниченный повтор получает конкретную подсказку о нарушении схемы, цитате
или шкале. Тексты ответов и секреты в диагностике не печатаются. Проверки не
ослаблены, ответы автоматически не подменяются. В адресном v6 повторов не было,
поэтому успешность механизма уточняющего повтора подтверждена тестами,
а не приписана этому живому запуску.

Ключ находится в игнорируемом `.env`. Сканирование подготовленных к коммиту
исходников на значения локальных секретов не выявило совпадений. Исходный DEV,
полные модельные ответы и рабочая SQLite-база остаются вне Git.

## Повторить проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s backend/tests -v
.\.venv\Scripts\python.exe -m pip check
npm --prefix frontend run build
```

Для браузерного сценария нужен Python с Playwright и Google Chrome. Запустить
отдельную тестовую базу:

```powershell
$env:CQA_BROWSER_TEST = '1'
$env:CQA_BROWSER_TEST_DB = 'scratch/browser-test.sqlite3'
.\.venv\Scripts\python.exe -m uvicorn backend.tests.browser_fixture:create_browser_app --factory --host 127.0.0.1 --port 8001
```

Во втором терминале:

```powershell
python scripts/browser_smoke.py --url http://127.0.0.1:8001
```

Скрипт отказывается изменять сервер, если `/api/config` не содержит `mode=test`.
Тестовый оценщик не включён в обычный запуск. Снимки и отчёты лежат в `scratch/`.

## Что остаётся внешней проверкой

Официальный Ground Truth не предоставлен. Шаблон `data/evaluations/labels.official.json`
содержит 24 диалога без выдуманных эталонных ответов. Независимая разметка должна
предшествовать заявлению о точности; родственные сценарии и переводы нельзя разносить
между обучением и контрольной частью. Согласие моделей само по себе не показывает,
какая из них права.

Контрольные 10 чатов пока не получены. Их требуется импортировать, реально оценить
и сохранить как `results/prod/results.json`. Рабочая модель анализирует текст;
наличие аудиоплеера не означает, что модель прослушивает запись. Продуктовая база
знаний с актуальными тарифами и сроками не предоставлена.

Выборочная сверка v6 подтвердила существование 124 цитат и 16 диапазонов в восьми
DEV-ответах. Уточнение про отозванную догадку устранило конкретное ложное
срабатывание на раскрытие данных. Это не полная человеческая разметка: трактовки
ясности и завершения шумного звонка, отдельных шкал и эмпатии остаются спорными.
