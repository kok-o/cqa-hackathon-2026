Чек-лист и приложение получены 7 ноября 2026 года. Перед копированием проверены оба PDF: в каждом **0 ссылок, 0 аннотаций, 0 вложенных файлов**. Подписанные ссылки и ключи в этих копиях не обнаружены. Для получения DEV адрес кнопки на странице 3 исходного гайда сохраняется только в локальной переменной `CQA_DEV_URL`.

Рабочая конфигурация — [checklist.official.json](../../fixtures/checklist.official.json). Восемь ID: `contact`, `discovery`, `identification`, `consultation`, `empathy`, `dialogue`, `closure`, `critical`; веса: 10 / 15 / 20 / 20 / 15 / 15 / 5 / 0. [Расчёт](../SCORING.md) описывает пропорциональное перераспределение N/A и отдельный флаг грубой ошибки. Двухкритериальный `checklist.example.json` остаётся синтетической тестовой конфигурацией.

Приложение требует `results/dev/results.json` для 60 чатов и 5 звонков и `results/prod/results.json` для 10 контрольных чатов; один исходный ID — одна запись, включая ошибки. `value=null` означает только N/A. Ошибка обработки передаётся как `status="error"`, пустой `criteria`, `score=null` и причина. Успешная запись содержит все восемь критериев. Пример на странице 2 вымышленный и не является официальной разметкой DEV.

Согласно приложению, результаты должны быть доступны организаторам в указанном ими открытом репозитории после commit и push до стоп-кода. На 8 ноября репозиторий открыт по запросу владельца, оба файла DEV/PROD находятся в main. Передача ссылки через канал организаторов остаётся отдельным действием команды. Исходные транскрипты, токены, runtime-БД и подписанный исходный гайд не входят в эти копии материалов.
