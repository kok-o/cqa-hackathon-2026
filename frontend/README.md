# Интерфейс — Олжас

Стек проекта — React, TypeScript и Vite. Интерфейс должен собираться в обычные HTML/CSS/JS-ресурсы. Корневой контейнер CQA, стили компонентов и API-адаптер изолируются для дальнейшего встраивания в Dynamics 365.

В текущем стартовом наборе подготовлены `src/contracts.ts` и описание экранов. Первым изменением создайте Vite-приложение внутри `frontend/`, сохранив эти контракты. Закрепите версии зависимостей в `package-lock.json`.

## Первый работающий маршрут

1. Получить `GET /api/demo/conversations` из каркаса.
2. Показать список и выбранный транскрипт.
3. Присвоить каждой реплике DOM-якорь по `message_id`.
4. Подключить таблицу синтетического результата и переход по evidence-ID.
5. После готовности сервера переключить API-адаптер на реальные endpoints.

В разработке Vite проксирует `/api` на `http://127.0.0.1:8000`. Для демонстрации сборку раздаёт сервер. Ключ модели и подписанный URL источника доступны серверной части.

## Экраны

- Диалоги. Язык, канал, выбранный запуск, статус проверки.
- Чек-лист. Список версий и редактор критериев с валидацией.
- Диалог. Транскрипт, аудио, оценка по критериям, итог и ссылки на доказательства.
- Апелляции. Комментарий и контекст критерия, действие проверяющего, причина и история.

Для каждого запроса предусмотрите загрузку, ошибку, пустой результат и повтор. При переходе между диалогами отменяйте устаревший запрос или проверяйте его ID перед отображением.

В интерфейсе всегда видны версия чек-листа и статус оценки. Неопределённость отображается явно. Цвет статуса сопровождается текстом. Длинные диалоги сохраняют читаемость, управление доступно с клавиатуры.

Официальные руководства — [React](https://react.dev/learn), [Vite](https://vite.dev/guide/).
