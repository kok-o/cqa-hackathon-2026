# Файлы сдачи SetW

Официальный формат: JSON 1.0 из `docs/briefs/CQA_Student_Guide_Appendix_Results.pdf`.

- `dev/results.json`: 65 исходных DEV-диалогов — 60 чатов и 5 звонков; Luna/high, 65 `ok`, 0 `error`.
- `reference/sol-dev-v3.json`: сохранённые 65 оценок Sol/max/v3 для сравнения; это не Ground Truth и не основной файл сдачи.
- `prod/results.json`: 10 контрольных чатов, которые выдадут организаторы.

PROD нельзя заменять учебными примерами или дублировать из DEV. Папка PROD и файл
появятся только после получения и реальной оценки контрольного набора.

Текущий DEV объединяет 57 завершённых оценок Luna/v5 и 8 адресно перепроверенных
Luna/v6. Все исходные ответы и стоимость заменённых попыток сохранены локально;
это не единый чистый прогон v6. Следующие оценки приложение выполняет на v6.
Подробности и ограничения — в [отчёте сравнения](../docs/BENCHMARK_RESULTS.md).

## Через приложение

1. Импортировать исходный JSON набора. Для контроля использовать фактический
   `dataset_group_id` из файла организаторов.
2. Выбрать официальный чек-лист и запустить оценку нужной группы. Дождаться
   завершения задач; проверить ошибки и полноту по всем критериям.
3. Нажать «Файл для сдачи»: команда **SetW**, соответствующая группа, раздел
   DEV или PROD, модель `gpt-6-luna`, режим «Внешний API».
4. Скачать `results.json` и сохранить в соответствующую папку выше. Экспорт
   содержит всю группу, независимо от языковых и прочих фильтров интерфейса.
   Проверить показанные количества успешных записей и ошибок.
5. Проверить файл командой ниже и выполнить commit/push до дедлайна организаторов.

```powershell
python -m evaluation.submission validate --dataset data/raw/DEV.json --split dev --input results/dev/results.json
# Для контроля заменить исходный путь и оба dev на prod.
```

Экспорт использует исходные ответы модели до апелляций и утверждённые правила.
Необработанная или неполная оценка даёт `status="error"`, а не выдуманный ноль.
Любое обновление правил для официальной сдачи должно соответствовать указаниям
организаторов; произвольный изменённый вес нельзя выдать за исходный JSON 1.0.

## Повторная выгрузка сохранённых результатов

Основной смешанный набор уже импортирован в локальное приложение. Его можно
выгрузить без новых API-вызовов через форму выше или HTTP:

```powershell
Invoke-WebRequest 'http://127.0.0.1:8000/api/submission/export?group_id=DEV&split=dev&team_name=SetW&model_name=gpt-6-luna&model_mode=external_api' -OutFile results/dev/results.json
```

Используйте порт работающего сервера (в текущей локальной сессии — 8015).
Команда намеренно заменяет существующий файл; затем выполните проверку выше.
Для восстановления локальной базы сначала импортируйте исходный набор DEV,
затем сохранённые результаты в указанном порядке:

```powershell
python scripts/import_benchmark.py --run-dir data/evaluations/full-dev-luna-v5 --dry-run
python scripts/import_benchmark.py --run-dir data/evaluations/full-dev-luna-v5
python scripts/import_benchmark.py --predictions data/evaluations/luna-v6-dev-updates.json --dry-run
python scripts/import_benchmark.py --predictions data/evaluations/luna-v6-dev-updates.json
```

Файл обновлений содержит только восемь DEV-записей из targeted-v6; синтетические
примеры не импортируются в рабочую базу. Повторный импорт не создаёт дублей.
Эти приватные артефакты находятся на машине автора, в Git они не включены.
Для одного нового полного запуска доступен CLI `python -m evaluation.submission export --help`;
объединять два перекрывающихся прогона без выбора последних
результатов нельзя.

Текущий репозиторий остаётся закрытым по запросу владельца. Приложение к заданию
требует открытого репозитория для сдачи; видимость меняет владелец перед отправкой.
Ключи, signed URL, исходные записи и рабочая SQLite-база не должны попадать в Git.
